# ระบบยืม-คืนกายอุปกรณ์การแพทย์

เว็บแอปสำหรับศูนย์ยืม-คืนกายอุปกรณ์การแพทย์ ครอบคลุมการลงทะเบียนผู้ยืม การยืม-คืน คำขอยืมจากผู้ใช้ทั่วไป การนับสต็อก และ audit log

**การจัดเก็บข้อมูล**: PostgreSQL (Neon) สำหรับข้อมูล และ Vercel Blob สำหรับรูปภาพ deploy บน Vercel
วิธีติดตั้งดูที่ [`DEPLOY.md`](DEPLOY.md)

## เริ่มต้นใช้งาน (รันบนเครื่องตัวเอง)

```bash
npm install
cp .env.example .env.local   # แล้วแก้ค่าให้ครบ (ดู DEPLOY.md ขั้นตอนที่ 3)
npm run check-env            # ตรวจว่าตั้งค่าครบก่อน
npm run db:migrate           # สร้างตารางในฐานข้อมูล
npm run seed                 # สร้างผู้ใช้ + อุปกรณ์ตัวอย่าง
npm run dev                  # http://localhost:3000
```

| หน้า | URL | ต้อง login |
|---|---|---|
| หน้าแรก | `/` | ไม่ต้อง |
| ฟอร์มคำขอยืม | `/request` | ไม่ต้อง |
| ระบบเจ้าหน้าที่ | `/staff` | ต้อง |

**บัญชีเริ่มต้น**: username `admin` และ `staff` · รหัสผ่านคือค่าที่ตั้งไว้ใน
`SEED_ADMIN_PASSWORD` / `SEED_STAFF_PASSWORD` ตอนรัน seed — ระบบไม่มีรหัสผ่านเริ่มต้นให้
เพื่อไม่ให้มีบัญชีที่เดารหัสได้หลุดขึ้น production

**เจ้าหน้าที่เข้าระบบด้วยพาสคีย์** รหัสผ่านเป็นแค่ตั๋วเข้าครั้งแรก: login ครั้งแรกแล้วระบบ
จะบังคับสร้างพาสคีย์ทันที เข้าหน้าอื่นไม่ได้จนกว่าจะเสร็จ · หลังจากนั้นรหัสผ่านเดิม
**ใช้ login ไม่ได้อีก** เพราะพาสคีย์คือสิ่งเดียวที่เว็บปลอมเอาไปใช้ต่อไม่ได้
· รายละเอียดและวิธีกู้คืนตอนทำอุปกรณ์หายอยู่ใน `DEPLOY.md`
· **ตอน dev ต้องเปิดที่ `http://localhost:3000` ไม่ใช่ `127.0.0.1`** — พาสคีย์ผูกกับชื่อโดเมน ใช้ IP ไม่ได้

## สิ่งที่ระบบทำ (ตามสเปกแต่ละโมดูล)

**4.1 ลงทะเบียนผู้ยืม** — ฟอร์มลงทะเบียน (ชื่อ, เลขบัตร ปชช., ที่อยู่, รูปบัตรประชาชน, รูปอาการป่วย, คำอธิบาย) ตรวจสอบเลขบัตร 13 หลักด้วย checksum จริงของไทย **รูปบัตรประชาชนบังคับแนบ** เพราะเจ้าหน้าที่ต้องตรวจก่อนอนุมัติ ส่วนรูปอาการป่วยไม่บังคับ บันทึก timestamp อัตโนมัติ เลขบัตรประชาชน**เข้ารหัส AES-256-GCM**ก่อนเก็บ (คีย์มาจาก `ENCRYPTION_KEY`) หน้าจอทั่วไปแสดงเลขบัตรแบบ mask (เช่น `110xxxxxxx366`) ต้อง login ก่อนถึงจะเห็นเลขเต็มและรูปภาพ

**4.2 ยืม-คืนอุปกรณ์** — จ่ายอุปกรณ์เริ่มจากหน้าของผู้ยืม (เลือกคนก่อน แล้วเลือกของ) ส่วนหน้ารับคืนมีแต่รายการที่ยังไม่คืน เลือกอุปกรณ์จากสต็อกจริง บันทึกวันที่ยืม/กำหนดคืน/สถานะ (ยืมอยู่ / คืนแล้ว / เกินกำหนด — คำนวณอัตโนมัติจากวันครบกำหนด) เมื่อคืนบันทึกวันที่คืนจริง สภาพอุปกรณ์ และผู้รับคืน ทุกการกระทำบันทึกผู้ทำรายการ (`handled_by` / `received_by`) และเขียนลง audit log

**4.3 คำขอยืม** — ฟอร์มสาธารณะที่ `/request` ไม่ต้อง login เข้าคิวสถานะ "รอดำเนินการ" เจ้าหน้าที่อนุมัติ/ปฏิเสธได้ในแท็บ "คำขอ" การอนุมัติจะสร้างรายการยืมจริงและตัดสต็อกทันที

**4.4 นับสต็อก** — แท็บ "สต็อก" แสดงจำนวนคงเหลือ/ถูกยืม/ทั้งหมดของทุกชิ้น อัปเดตอัตโนมัติทุกครั้งที่ยืม/คืน/อนุมัติคำขอ ขึ้นป้าย "สต็อกใกล้หมด" เมื่อจำนวนคงเหลือ ≤ threshold ที่ตั้งไว้ (แก้ไขได้)

**4.5 ประวัติ / Audit log** — แท็บ "ประวัติ" แยก 3 มุมมอง: ประวัติผู้ยืมรายคน (พร้อมสรุป % คืนตรงเวลา), ประวัติอุปกรณ์รายชิ้น, และ Audit log แสดงทุกการกระทำพร้อมชื่อเจ้าหน้าที่ที่ทำรายการ

## ความปลอดภัยและ PDPA

- **เลขบัตรประชาชน** เข้ารหัส AES-256-GCM ก่อนบันทึกเสมอ · หน้ารายการเห็นแบบปิดบัง (`110xxxxxxx366`)
  · ค้นหาด้วย keyed hash ไม่ต้องถอดรหัสทั้งตาราง
- **รูปบัตร ปชช. / รูปอาการป่วย** เป็นข้อมูลสุขภาพ เก็บเป็น **private blob** และเสิร์ฟผ่าน
  `/api/files/...` ที่ตรวจ session เท่านั้น · URL หลุดไปก็เปิดไม่ได้
  · ทุกไฟล์ถูก decode แล้ว re-encode ใหม่ด้วย `sharp` ซึ่งพิสูจน์ว่าเป็นรูปจริง (ไม่เชื่อ MIME
  ที่ browser ส่งมา) และ**ลบ EXIF ทิ้ง** — รูปถ่ายจากมือถือมีพิกัด GPS ฝังอยู่
  แปลว่ารูปบัตรที่ถ่ายที่บ้านคนไข้จะพาที่อยู่จริงติดไปด้วย
- **ทุกการกระทำที่มีผลต่อข้อมูล** ถูกบันทึกใน audit log พร้อมชื่อผู้ทำรายการ
- **Rate limit** ที่หน้า login (กันเดารหัสผ่าน) และฟอร์มคำขอสาธารณะ (กันสแปม)
  · นับเฉพาะครั้งที่ล้มเหลว และแยก bucket ต่อคู่ (ผู้ใช้, IP) เพื่อไม่ให้ใครยิงรหัสผิด
  ใส่ `admin` แล้วล็อกแอดมินตัวจริงออกจากระบบได้
- **พาสคีย์ (WebAuthn)** เป็นทางเข้าเดียวของเจ้าหน้าที่หลังตั้งค่าแล้ว — กันฟิชชิ่งได้จริง
  เพราะ credential ผูกกับชื่อโดเมน
- **ปิดบัญชีแล้วมีผลทันที** ทุก request เช็คแถวผู้ใช้จริง ไม่ได้เชื่อ cookie อย่างเดียว
  · เปลี่ยนรหัสผ่าน / ปิดบัญชี / รีเซ็ตพาสคีย์ = ตัดทุกเครื่องที่เปิดค้างไว้
- **บันทึกการเปิดดูข้อมูลส่วนบุคคล** ไม่ใช่แค่การแก้ไข — PDPA ให้สิทธิ์เจ้าของข้อมูลถามว่าใครดูบ้าง
- **ข้อมูลอยู่นอกประเทศไทย** (สิงคโปร์) — ถ้าต้องการให้อยู่ในไทย ดูหัวข้อใน `DEPLOY.md`
- **ลบข้อมูลส่วนบุคคลอัตโนมัติ** 2 ปีหลังการยืมครั้งสุดท้าย ตามที่ประกาศ PDPA บอกไว้
  · เก็บแถวและประวัติการยืมไว้ (ไม่งั้น audit log อ่านไม่รู้เรื่อง) แต่ล้างทุกอย่างที่ระบุตัวคนได้
  · ตรวจก่อนด้วย `npm run retention:preview`
- **กันบอทที่ฟอร์มสาธารณะ** ด้วย Cloudflare Turnstile (ไม่ใส่ key = ปิดไว้)
- ผลการตรวจความปลอดภัยทั้งเว็บ และสิ่งที่ยังต้องตั้งค่าเองใน Vercel/Neon อยู่ใน **`SECURITY.md`**
